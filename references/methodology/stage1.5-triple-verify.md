# 阶段 1.5 — 三重验证筛选

对每个候选单元执行三项检验，**三项全过**才进入 `verified.md`。

## V1 跨域（Cross-reference）
原内容中至少有 **2 处独立段落/位置** 佐证该单元？
- 只有 1 处孤证 → 存疑，除非是作者明确定义的核心概念。
- 用阶段 0 保留的原文位置回溯确认。

## V2 预测力（Predictive power）
能用它回答一个**原内容没明说**的新问题吗？
- 测试方法：构造一个书里没有、但属于同一方法论域的新情境，看该单元能否给出可执行指引。
- 不能迁移到新情境 → 只是描述性内容，淘汰。

## V3 独特性（Non-trivial）
它不是「任何聪明人都懂的常识」吧？
- 通用道理（如「要专注」「多练习」）→ 淘汰。
- 有具体机制、可操作、带边界的方法论 → 保留。

### V3 附加：公开理论阈值过滤（移植自 yizhan-shendeng v2）
方法论类内容会大量转述已广泛流传的公开框架（创新扩散、S 形曲线、SWOT、PEST、波特五力、MECE、金字塔原理、第一性原理等）。这类内容原文支撑充分、也有预测力，V1/V2 都能过，但 Agent 本就会，做成 skill 等于教它已会的东西。处理：
- **理论本身一律淘汰**，不论作者讲得多透、占多少篇幅。
- **但保留作者在理论上加的具体阈值 / 判据 / 操作步骤**。界线是「能不能直接拿去判断一个具体案例」：说得出名字但用不上手的是理论（淘汰）；能对着真实行业算出答案的是作者贡献（保留）。例：「产业分导入/成长/成熟/衰退四阶段」是教科书内容（淘汰）；「用渗透率 15%–20% 进成长期、35%–40% 后进成熟期」是可操作判据（保留）。

## 主料 / 配料分离（移植自 yizhan-shendeng v2）

五路候选不是同一种东西，不要一起验：
- **主料（框架、原则）**：会变成 skill 本身，过全部三重验证。
- **配料（案例、反例、术语）**：只支撑「怎么做 / 出处 / 边界」，只做去重，**不验证**。

理由：案例与反例本就不是独立洞察，让它们过「是不是常识」会被大量误杀；而反例一旦被杀光，阶段 2 的 B 段（何时不该用）就没有素材来源。术语去重后回写骨架的「关键概念」一节，供阶段 2 写 description 时判断哪些词是书里的术语、不该出现在用户会说的话里。

先合并去重框架与原则（同洞察不同表述合并），再逐条过三重验证，三条全过才留。

## 通过率自校准（移植自 yizhan-shendeng v2）

统计通过率（分母只算框架 + 原则的条数，不含配料）。

| 输入类型 | 正常区间 | 过高线 | 过低线 |
|----------|----------|--------|--------|
| 书 | 30%–50% | 高于 65% | 低于 8% |
| 转写稿 | 15%–30% | 高于 45% | 低于 5% |

- 高于过高线：V3 放水，收紧常识 / 公开理论判据，重筛一次。
- 低于过低线：V1 卡太死，放宽佐证判据，重筛一次。
- **无论结果，只重筛一次**，第二次直接放行（防全自动流程反复重筛烧额度）。

## 全军覆没降级（移植自 yizhan-shendeng v2）

重筛后通过数仍为 0：不静默失败、不硬造。把提取到的原始候选留在 `candidates/`，向用户说明「没有一条同时满足三验证，通常意味着观点较通用」，并停止。淘汰条目连同原因写入 `candidates/淘汰记录.md`，最终清单引用。

## 处置

- 通过：写入 `verified.md`，含「单元名 + 类型 + 判定理由（V1/V2/V3 如何满足）」。
- 不通过：写入 `rejected/<unit>.md`，附「淘汰原因（哪项未过 + 说明）」。

## 用户轻确认 ★

筛选完成后，展示列表：
```
通过 N 个候选:
  - <单元名1>（框架）
  - <单元名2>（原则）
  ...
淘汰 M 个（已存 rejected/，可捞回）:
  - <单元名3>：V3 未过（常识）
  - ...
```
问用户：「这 N 个会做成 skill，有想捞回或砍掉的吗？」确认后再进阶段 2——阶段 2–4 最耗时，此步确认避免大量返工。
